# 保险金额与保险费的计算链（实单验证）

> 依据：业务 302（FOB 出口）对手填写的有效投保单 MI0000867 + 我方出口报关单 020000814。
> 结论：**保险费与 CIF 价存在循环依赖，必须用代数解，不能用顺序计算。**

## 二、计算链

已知：FOB 价 `P` = 76220，运费 `F` = 760，加成率 `k` = 110%（即 1.1），费率 `r` = 0.88%。

保险费由 CIF 决定，而 CIF 又包含保险费，所以：

```
CIF = P + F + I
I   = CIF × k × r
⟹ CIF = (P + F) / (1 − k × r)
```

代入验证：

```
CIF = (76220 + 760) / (1 − 1.1 × 0.0088)
    = 76980 / 0.99032
    = 77732.42 ≈ 77732.45   ✓（系统保留 2 位小数）
I   = 77732.45 × 1.1 × 0.0088 = 752.45   ✓
保险金额 = 77732.45 × 1.1 = 85505.69     ✓
```

**顺序计算会算错**：若先按 FOB 算保费再算 CIF，保费会偏小（76220×1.1×0.88% = 737.9，与实际的 752.45 差 14.5 美元）。

## 三、对程序的要求

1. **不能用顺序公式**，必须解这个一元方程。CIF/CFR 术语下无需此步（价格已含运费/保险），只有 FOB/FCA/CPT 且需要投保时才算。
2. **费率单位是千分率**。界面显示 `8.80`，实际参与运算是 `0.0088`。若按百分数处理，保费会放大 10 倍。
3. **保费要回写到报关单**的「保费」栏，运费回写到「运费」栏，两者必须与投保单一致。
4. 费率与险别挂钩（一切险 / 水渍险 / 平安险 / ICC(A)(B)(C)），且特殊附加险（战争险、罢工险）不额外累加费率——百科原文："战争险与罢工险两项险别，如同时加保，费率不累加，仍按只投其中一项计"。

## 四、投保单的字段来源映射（补进模型）

| 投保单栏位 | 来源 |
|---|---|
| 投保人 / 被保险人 | 负责投保的一方（CIF/CIP→出口商；FOB/FCA/CFR/CPT→进口商） |
| 投保人地址 / 邮编 / 电话 | 该公司档案 `address_en` / `postcode` / `tel` |
| 联系人 | 该公司 `legal_en`（英文单据）或 `legal_zh`（中文单据） |
| 贸易合同号 | `deal.contract_no` |
| 信用证号 | `deal.lc_no`（非 L/C 留空） |
| 标记 | `deal.shipping_mark`（本例 N/M） |
| 包装及数量 | `pack_total + pack_unit` |
| 保险货物项目 | `goods.name_en` |
| 起运日期 | 装运日期（本例 2026-11-15，晚于发票日期 5 天） |
| 赔付地点 | `port_dest`（英文+国别） |
| 航行路线 | `port_load` → `port_dest` |
| 承保条件 | `deal.insurance_cover` |
| 加成 / 费率 | `deal.insurance_rate`（110%）/ 费率表 |
| CIF 金额 / 保险金额 / 保险费 | 按上面公式算 |
| 投保人签字 | 投保方 `name_en` |
| 日期 | 发票日期 |
